Ideas and planned work for ZeremAI, the Claude Code plugin, grouped by area and sorted by priority. Nothing here is a commitment or has a date. Open an [issue](https://github.com/HMTools/ZeremAI/issues) to suggest something.

**22** planned · **8** shipped

## Framework (plugin)

<AccordionGroup>
<Accordion title="Explicit step type: spawn and direct">
*RM-001 · feature · 🔴 High*

Add a stepType field (spawn for a sub-flow, direct for a regular step) so the type is declared, not inferred from subFlowTrigger. Show it in the flow pane and link a spawn step to its target template.
</Accordion>

<Accordion title="Dynamic context injection in the flow-run skill">
*RM-005 · improvement · 🔴 High*

Use dynamic context injection in the flow-run skill so it loads only what the current step needs, cutting token use.
</Accordion>

<Accordion title="Event system for flow lifecycle">
*RM-008 · feature · 🔴 High*

Emit events for flow lifecycle moments (created, step started, step approved, completed, failed). Support global and template-level listeners, with several subscribers per event.
</Accordion>

<Accordion title="Loop-back execution in flows">
*RM-034 · feature · 🔴 High*

Templates already accept loopBackTo, loopCondition and maxIterations. Make the flow runner honor them: reset the target step, jump back, and stop at a loop-depth limit to prevent infinite cycles.
</Accordion>

<Accordion title="Verification checklist per step">
*RM-003 · feature · 🟡 Medium*

Add a verification checklist to each step, checked by a hook or by a low-cost model in a subagent, to confirm a step is really complete.
</Accordion>

<Accordion title="Git management: branches, tagging, worktrees">
*RM-010 · feature · 🟡 Medium*

Git support for flows: create a branch per flow, tag milestones, and use worktrees to isolate parallel flows.
</Accordion>

<Accordion title="Dynamic flows and templates">
*RM-011 · feature · 🟡 Medium*

Let flows and templates generate or adapt their steps at runtime based on context.
</Accordion>

<Accordion title="Simple do template for ad-hoc workflows">
*RM-012 · feature · 🟡 Medium*

A simple built-in "do" template that builds a workflow on the fly from existing steps, then saves any new steps and the flow as a reusable template.
</Accordion>

<Accordion title="Smarter continuous improvement findings">
*RM-013 · improvement · 🟡 Medium*

Make the Continuous Improvement step find changes that make future flows one-shot, cheaper in tokens, and lighter on context, and rank them better before saving findings.
</Accordion>

<Accordion title="Per-step model configuration">
*RM-014 · feature · 🟡 Medium*

Choose the model per step (today the step-executor inherits the session model), so simple steps can run on cheaper models.
</Accordion>

<Accordion title="Cost analysis of flows and steps">
*RM-018 · feature · 🟡 Medium*

Track token use and cost per flow and per step to show where optimization pays off.
</Accordion>

<Accordion title="CI/CD triggers">
*RM-020 · feature · 🟡 Medium*

Triggers for CI and CD: start or advance a flow from a pipeline event.
</Accordion>

<Accordion title="Verification subagent as optional step declaration">
*RM-024 · improvement · 🟡 Medium*

Make a verification subagent (separate context window) an optional part of a step declaration, not a dedicated step.
</Accordion>

<Accordion title="Knowledge graph integration (graphify)">
*RM-019 · feature · ⚪ Low*

Integrate graphify to build a knowledge graph from flow data and explore relationships and dependencies.
</Accordion>

<Accordion title="Use full skills frontmatter capabilities">
*RM-021 · improvement · ⚪ Low*

Use more of the skills frontmatter spec (model choice, tool restrictions, other fields) in the plugin skills.
</Accordion>

</AccordionGroup>

## Flow pane (UI)

<AccordionGroup>
<Accordion title="Review improvement findings in the pane">
*RM-033 · improvement · 🔴 High*

Browse saved improvement findings in the flow pane as cards (category, what, why, impact, files) and approve, reject or defer them, instead of running /apply-improvements blind.
</Accordion>

<Accordion title="Live substep diagram in the flow pane">
*RM-027 · feature · 🟡 Medium*

The pane already draws the step graph of a bound flow. Add a live view of the active step's substeps and control flow as they run.
</Accordion>

<Accordion title="Track files modified across a whole flow">
*RM-028 · improvement · 🟡 Medium*

Show which files a flow changed anywhere in the project, not only what is in the flow folder, using the files recorded in the log.
</Accordion>

<Accordion title="Richer review in the approval dialog">
*RM-029 · improvement · 🟡 Medium*

Show step deliverables in the approval dialog as rich, easy-to-review views (diffs, tables, diagrams) instead of plain markdown.
</Accordion>

<Accordion title="Create templates by chat in the pane">
*RM-030 · feature · 🟡 Medium*

Design a template conversationally from the flow pane, with a live preview of its steps and parameters.
</Accordion>

<Accordion title="Memory view in the flow pane">
*RM-035 · feature · 🟡 Medium*

Show which steps read and write which memory topics, for templates and running flows, plus current contents, per-step history and diffs.
</Accordion>

<Accordion title="Full template details before install">
*RM-039 · feature · 🟡 Medium*

The Templates tab shows a short summary until a template is installed. Show all fields, parameters and steps on click, before installing.
</Accordion>

</AccordionGroup>

## Shipped

<AccordionGroup>
<Accordion title="Change memory from single file to multiple files">
*RM-004 · improvement*

Split the single memory file into topic-based memory files in the flow memory folder, with per-step read and write access.
</Accordion>

<Accordion title="Block hand edits of flow state files">
*RM-009 · feature*

The mod refuses Write, Edit and Bash writes to a flow's state files (flow, log, memory, findings) so only the flow script changes them. Only the user click can approve a step.
</Accordion>

<Accordion title="Default steps to template scope">
*RM-015 · improvement*

Change steps to default to template scope (related to specific template), with an option to set steps as global.
</Accordion>

<Accordion title="Step-level shared behaviors via hooks and skills">
*RM-016 · improvement*

Implement step-level shared behaviors (previously _components) through hooks and skills for cross-cutting concerns.
</Accordion>

<Accordion title="Remove view-only MD files, add view-page skill">
*RM-017 · improvement*

Remove the view-only markdown files and instead create a skill that generates interactive view pages from JSON definitions.
</Accordion>

<Accordion title="Step executor skill">
*RM-022 · feature*

Create a dedicated step executor skill for running individual steps with proper context isolation and state management.
</Accordion>

<Accordion title="Rebrand to ZeremAI">
*RM-032 · idea*

The framework is now ZeremAI, a Claude Code plugin, with the /zeremai command.
</Accordion>

<Accordion title="Create official framework wiki on Mintlify">
*RM-036 · documentation*

Public documentation site for ZeremAI on Mintlify: install, concepts, authoring, reference and this roadmap.
</Accordion>

</AccordionGroup>
